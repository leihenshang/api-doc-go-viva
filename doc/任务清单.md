## P1：编辑链路补齐

### N5 集合公共参数 + `inherit` 认证

- **来源**：Wails 对照。`CollectionDefaultsDialog.vue`（集合默认请求头 + 认证）；`auth.type = inherit`。
- **现状**：只能逐请求重复写公共头；认证没有继承，导入 Postman 的集合级 auth 会丢。
- **范围**：`internal/explorer`（集合根 `collection-defaults.yml` 读写）、`internal/send`（合并顺序：集合默认 → 请求，后者覆盖同名；`inherit` 取集合认证）、`internal/view`（集合页入口 + 认证下拉加「继承集合」）。
- **验收**：集合默认头在每条请求上都生效且不重复；请求显式同名头覆盖集合值；`inherit` 与直接写 bearer 产出相同 `Authorization`。

### N6 导出补「集合包」与 OpenAPI

- **来源**：Wails 对照。`collection/bundle.go`（`.apidocgo.json` 双向）、`collection/export_openapi.go`。
- **现状**：`internal/export` 只有 Markdown / HTML（含勾选范围）。
- **范围**：`internal/export` 加 `Bundle()`（整集合 JSON，可再被 `importers` 读回）与 `OpenAPI()`（3.0，路径按分组层级拼）；`internal/view/exportui.go` 的格式下拉加两项。
- **验收**：导出 → 导入回空目录 → 树结构、方法、URL、头、请求体字段一致；OpenAPI 产物能被本仓库的 `importers.OpenAPI` 解析回来。

### N7 历史详情

- **来源**：Wails 对照。`HistoryDialog` 的「详情」。
- **现状**：`internal/history` 只存方法 / URL / 状态 / 耗时 / 大小，点开只能回到请求。
- **范围**：`Entry` 补请求快照（头、参数、体摘要，正文超过 8KB 截断并标记）；`dialogs.go` 每行加展开区。
- **注意**：jsonl 会变大，配合上限裁剪；敏感头（`Authorization` / `Cookie`）落盘前打码。
- **验收**：详情里的方法与实际发出的一致；打码后原值不可见；老文件（无新字段）仍能读。

## P2：独立大件（动之前先评估）

### N8 gRPC

- **来源**：Wails 对照。`internal/proto` + `runner/grpc.go` + 四个编辑分段 + mTLS + grpcurl 代码生成。
- **现状**：树里能列出 gRPC 条目，点开是只读占位（`panes.go`：`验证版只读展示 gRPC 元数据，不发起调用。`）。
- **范围**：新包 `internal/grpc`（.proto 编译 → 描述符 → 动态消息 → unary + 三种流式）；`internal/view` 加 Schema / Message / Metadata / Options 四个分段；`codegen` 加 grpcurl。
- **风险**：这是唯一真正的协议缺口，工作量约等于当初的 runner；建议单独立项，不和 P0/P1 混做。

### N9 MCP 扩容

- **来源**：Wails 对照。36 个工具、六工具组、读写分级、Origin 白名单、交互授权（15 分钟 / 始终允许）、调用审计。
- **现状**：9 个工具（`internal/mcp/server.go`），无审计、无授权确认、无工具组、无 Origin 校验。
- **范围**：工具补齐（文档 / 环境 / 示例 / 网络分组）、`readOnly` 开关、授权弹窗、审计 jsonl + 导出。

### N10 Bruno 导入

- **来源**：Wails 对照。`collection/bruno_import.go` + `ImportBrunoDir`。
- **现状**：`internal/importers` 支持 Postman / OpenAPI / OpenCollection。
- **范围**：`importers/bruno.go`（`.bru` 文件解析：meta / get-post / headers / params / body / auth），导入对话框加一个格式入口。

### N11 运行器报告 + CLI

- **来源**：Wails 对照。`ExportRunReport`（JUnit）+ `cmd/clientctl run --reporter junit`。
- **现状**：`internal/runner` 有 extract/assert 与结果列表，报告的 JUnit 导出没有；也没有命令行入口。
- **范围**：`runner` 加 `JUnit(report)`；新增 `cmd/apidocctl`（`run` 子命令 + `--reporter text|junit`）。

### N12 托盘 / 自动更新 / 敏感值加密

- **来源**：Wails 对照。`internal/tray`、`app/update.go`、`internal/secrets`（AES-256-GCM + 系统密钥环）。
- **现状**：都没有；环境变量敏感值明文存 YAML。
- **说明**：三项可以拆开单做，优先级最低，但「敏感值明文」在真实使用中有风险，可以只做加密这一项。

### N13 JSON 请求体编辑器：行号与折叠

- **现状**：`TextArea` 只给纯文本。
- **卡点**：要有可编辑的代码编辑器；viva 目前没有暴露光标/选区，也没有可编辑的语法高亮层。
- **做法**：要么在 `internal/view` 自绘（透明 TextArea 叠着色层 + 行号槽），要么等上游。先做评估再决定。

### N14 文档编辑工具栏

- **现状**：文档编辑态只有纯 Markdown 原文。
- **卡点**：工具栏要「在光标处插入标记」，依赖 `TextArea` 的光标 / 选区接口，viva 尚未暴露。
- **备选**：不依赖光标——在正文末尾追加片段，或做「插入到选中行首」的降级实现。

### N15 截图重拍（T5 余量）

- **现状**：`doc/` 里已有新顶栏的概览 / 请求 / 文档 / 暗色四张；其余十几张还是带系统标题栏的旧图。
- **范围**：按 `screens/light/*` 的编号补拍，重点是列表页、环境、导入、设置、分栏、回收站。
- **注意**：截图脚本要用 `xdotool windowactivate` 先拿焦点，坐标按图像像素 1:1（窗口逻辑尺寸 = 截图尺寸），别按缩略图估算。

### N16 Postman v1 / Insomnia 导入

- **现状**：`importers/postman.go` 只吃 v2.1；Insomnia 完全不支持。
- **范围**：v1 的字段差异映射；Insomnia 的 `insomnia.json` 导出格式（环境与请求分组结构差别较大，先做只读导入）。

## 明确不做

与 `ui_reference/执行计划.md` §0 一致，以下不在范围内，不要因为对比而误开：

- 双向同步 / 服务端绑定 / 分享链接（Wails 有 `syncengine` 与 `share_browser`）；
- i18n 多语言、界面缩放 `uiScale`、多窗口；
- WebSocket / SSE（Wails 版也没有）；
- 冲突检测（外部改动哈希乐观锁）——若将来要做，入口是 `explorer` 的保存路径。
