### N9 MCP 扩容

- **来源**：Wails 对照。36 个工具、六工具组、读写分级、Origin 白名单、交互授权（15 分钟 / 始终允许）、调用审计。

### N11 运行器报告 + CLI

- **来源**：Wails 对照。`ExportRunReport`（JUnit）+ `cmd/clientctl run --reporter junit`。

- **范围**：`runner` 加 `JUnit(report)`；新增 `cmd/apidocctl`（`run` 子命令 + `--reporter text|junit`）。

### N12 托盘 / 自动更新 / 敏感值加密

- **来源**：Wails 对照。`internal/tray`、`app/update.go`、`internal/secrets`（AES-256-GCM + 系统密钥环）。

- **说明**：三项可以拆开单做，优先级最低，但「敏感值明文」在真实使用中有风险，可以只做加密这一项。

## 遗留自 `ui_reference/执行计划.md`

### N13 JSON 请求体编辑器：行号与折叠 ⏸ 卡在上游

- **现状**：`TextArea` 只给纯文本，没有行号、没有折叠，也拿不到光标与选区。
- **2026-11-20 尝试**：先给「响应正文」的只读视图加行号（左侧窄槽 + 折叠箭头右移）。实现本身能画出来，但改动了正文的 x 原点后 `handlePointer` 的箭头列判定与选区起点一起偏了，`TestSelectionTracksPointer` 直接选不出东西；同一次尝试还暴露出 viva 的 `Driver.Chord` 依赖「聚焦的文本终端」，指针在正文上按下会把焦点收回页面。
- **结论**：只读视图的行号可以单独立项做（不动 `sel.x`，把行号画在正文右侧或状态栏），但可编辑编辑器的行号 + 折叠必须有 viva 的 `TextArea` 光标/选区接口，强行自绘会把中文输入法（见 `doc/ime-linux.md`）一起搭进去。
- **下一步**：等 viva 暴露 `TextArea` 的光标/选区，再一次性做「行号 + 折叠 + 语法高亮」。

### N14 文档编辑工具栏

- **现状**：文档编辑态只有纯 Markdown 原文。
- **卡点**：工具栏要「在光标处插入标记」，依赖 `TextArea` 的光标 / 选区接口，viva 尚未暴露。
- **备选**：不依赖光标——在正文末尾追加片段，或做「插入到选中行首」的降级实现。

### N15 截图重拍（T5 余量）

- **现状**：`doc/` 里已有新顶栏的概览 / 请求 / 文档 / 暗色四张；其余十几张还是带系统标题栏的旧图。
- **范围**：按 `screens/light/*` 的编号补拍，重点是列表页、环境、导入、设置、分栏、回收站。

## 明确不做

与 `ui_reference/执行计划.md` §0 一致，以下不在范围内，不要因为对比而误开：

- 双向同步 / 服务端绑定 / 分享链接（Wails 有 `syncengine` 与 `share_browser`）；
- i18n 多语言、界面缩放 `uiScale`、多窗口；
- WebSocket / SSE（Wails 版也没有）；
- 冲突检测（外部改动哈希乐观锁）——若将来要做，入口是 `explorer` 的保存路径。
